## MiniMax-H3 OOM 排查（4×A100 40GB）
- 现象：镜像从 4×H100 80GB 迁到 4×A100 40GB 后 sglang serve OOM。
- 根因：`docker-compose.4xa100.yml` 旧注释显存估算错误。TP2 只把权重对半切（~31G/卡），Ulysses 只切序列/激活、不切权重。transformer 61.7G + text_encoder(Qwen3VL) 62.1G + vae 9.7G(bf16)，TP2+Ulysses2 每卡≈75G >> 40G。在 80G H100 上仅勉强塞下。
- 修复：改用 2 卡版已验证的省显存配方——`performance-mode memory` + `layerwise-offload-components dit,text_encoder,vae`(`--dit-offload-prefetch-size 1`, `--dit-layerwise-resident-layers 24`)，并移除 `--encoder-parallel auto`(层卸载不可与之混用)。TP2+Ulysses2 不变，用满 4 卡。
- 前置：层卸载需宿主机空闲内存 ≥~256G(理想 384G+)。
- 备选：主机内存不足时可用 TP4+Ulysses1 常驻，但 VAE 若被复制可能仍 OOM，需 nvidia-smi 实测。
- 权重体积来源：各组件 `*.safetensors.index.json` 的 `total_size`。

## MiniMax-H3 模型加载 AttributeError / NCCL 级联报错
- 现象：远程起 docker-compose.4xa100.yml 后报 `AttributeError: module diffusers has no attribute MiniMaxH3DiTModel`，随后 NCCL `ncclRemoteError: Connection closed by remote peer`，多 rank 崩。
- 根因：`--model-path` 指向手动下载到本地的仓库根目录(`/models/MiniMax-H3`，含 FL2VA/Ref2VA 子目录)。sglang 检测到本地路径后回退到原生 diffusers 加载路径，原生 diffusers 没有 MiniMax-H3 专属类 `MiniMaxH3DiTModel`(该类由 `sglang[diffusion]` 原生实现，不在 diffusers 里) → 该 rank 崩溃 → 其余 rank NCCL 连接被关。NCCL 报错是结果不是原因。
- 官方约束(SGLang cookbook)：① 不要手动把 `--model-path` 指向子目录，sglang 自带 checkpoint-directory 映射；② 不需 minimax-h3 diffusers fork。
- 镜像 `minimax-h3-sglang:latest` 从本机原样迁移，故差异在模型文件而非镜像。
- 修复方向(方案A推荐)：把本地仓库软链/放成 HF 缓存快照(`models--MiniMaxAI--MiniMax-H3/snapshots/<rev>/`)，用 `--model-path MiniMaxAI/MiniMax-H3` + `HF_HUB_OFFLINE=1` 让 sglang 走原生实现；或联网直接拉 MiniMaxAI/MiniMax-H3(或 ModelScope `MiniMax/MiniMax-H3` + `SGLANG_USE_MODELSCOPE=true`)。layerwise-offload 配置与此修复不冲突，继续有效。
- 已落地方案A(离线)：新建 `scripts/setup-offline-hf-cache.sh`，把 `/model_nas/models/MiniMax-H3` 顶层条目 symlink 为 HF 离线缓存快照 `models--MiniMaxAI--MiniMax-H3/snapshots/<40hex-rev>/`，target 用容器内路径 `/models/MiniMax-H3/<entry>`；`refs/main` 写该 rev。compose 改动：`--model-path` 改为 `MiniMaxAI/MiniMax-H3`；新增挂载 `/model_nas/hf_cache:/root/.cache/huggingface:rw`(rw 因 sglang 写 lock/refs)，保留 `/model_nas/models/MiniMax-H3:/models/MiniMax-H3:ro`(symlink 解析目标)；`HF_HUB_OFFLINE=1` 已设。注意 docker-compose.4xa100.yml 一度缺失，内容已并入 docker-compose.yml，本次已重建 docker-compose.4xa100.yml 副本，两者一致。启动：先跑 setup 脚本再 `docker compose up`。
